# Outline Tree

A publication's outline, from the opt-in publishing package
(`@knkcs/fieldkit/publishing`, ADR-0002 amended): a tree of nodes, each
described by one Blueprint Release the Field pins.

## Value

```ts
interface OutlineNode {
  _id: string;                       // unique across the whole tree (ADR-0023)
  values?: Record<string, unknown>;  // the node's Fields, keyed by Accessor
  origin?: "generated" | "manual";   // TOC generation: generated, or added by hand
  overridden?: boolean;              // an editor changed a generated node
  source?: string;                   // the id of the Content the node stands for
  children?: OutlineNode[];
}
```

The node is strict: any other key is refused. `origin`, `overridden` and
`source` are what contenthub's TOC generation reads; fieldkit only holds them.
`overridden: false` is a value (ADR-0021) and is stored as written, but means
what absent means, so a writer leaves it absent.

A node's `values` are checked against the Field's `children` — the Blueprint
Release `resolveSpec()` inlines from `settings.blueprint`. Unresolved, they
are an opaque record.

## Settings

| Setting     | Pin kind    | Description |
|-------------|-------------|-------------|
| `blueprint` | `blueprint` | The Blueprint Release declaring every Field a node can carry (a `kind` select among them). Inlined as `children` by Resolve. |
| `text_type` | `text_type` | The Text Type Release the outline's rich text is stamped with. Stored in the Resolved Spec's `parts`; fieldkit never reads it. |

The node Fields sit in the `reference_spec` Position (ADR-0022): no
container, no Marker. The outline itself sits at the root of a Blueprint only.

## UI

Not ported yet (#267). The control shows how many nodes the outline holds,
read-only, and never writes the value; a Consumer that edits outlines attaches
its own component: `{ ...outlineTreePlugin, fieldComponent: Mine }`.

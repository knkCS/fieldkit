# SpecForm

Renders a full specification as a form, automatically splitting it into
section tabs when the schema contains `section` fields. Wraps
[FieldRenderer](?path=/story/renderer-fieldrenderer--default) and adds
tabbed navigation, cross-tab field search, per-tab dirty/error indicators,
submit-jump-to-error, a loading skeleton, and a form-free read mode.

## When to Use

`FieldRenderer` stays public for flat embedding (groups use it internally to
render each item's child fields); embed `SpecForm` unless you know why not.
It is the entry point consumers should reach for when rendering a
specification end to end — including specs with no sections at all, where it
behaves identically to `FieldRenderer`.

## Props

| Prop       | Type                       | Default  | Description                                                        |
|------------|----------------------------|----------|---------------------------------------------------------------------|
| `schema`   | `Schema`                   | —        | The field specification to render.                                  |
| `mode`     | `"edit" \| "read"`         | `"edit"` | `"read"` renders values through each plugin's `readComponent`, or its table cell, instead of inputs. |
| `readOnly` | `boolean`                  | —        | Edit-mode only; disables inputs but keeps the form interactive.      |
| `loading`  | `boolean`                  | —        | Renders `SpecFormSkeleton` instead of the schema.                    |
| `values`   | `Record<string, unknown>`  | `{}`     | Read-mode data source. Ignored in edit mode.                         |
| `labels`   | `SpecFormLabels`           | —        | Overrides for the default-tab name, search placeholder, no-results text, markers, and indicator announcements. |

`SpecFormLabels` fields (`defaultTab`, `searchPlaceholder`, `searchLabel`,
`noResults`, `optionalMarker`, `tabErrors`, `tabErrorsOne`, `unsavedChanges`,
`booleanYes`, `booleanNo`) are all optional and merge over `DEFAULT_LABELS`.

| Label | Default | Description |
|-------|---------|--------------|
| `optionalMarker` | `"(optional)"` | §10 marker shown after non-required labels when the form is mostly required. |
| `searchLabel` | `"Find field"` | Accessible name (aria-label) of the field-search input. |
| `tabErrors` | `"{count} invalid fields"` | Accessible name of a tab's error badge; `{count}` is interpolated. |
| `tabErrorsOne` | `"1 invalid field"` | Accessible name of a tab's error badge at count 1 — used instead of `tabErrors` so the badge reads as a grammatical singular. |
| `unsavedChanges` | `"Unsaved changes"` | Accessible name of a tab's dirty dot — and, on anker ≥3.2, of a dirty field's own per-field dot. On anker 3.1 the per-field dot is still labeled, just with anker's hardcoded German default rather than this override, which only takes effect on ≥3.2. |
| `booleanYes` | `"Yes"` | Read-mode fallback rendering of boolean `true` for plugins with no `cellComponent`. |
| `booleanNo` | `"No"` | Read-mode fallback rendering of boolean `false` for plugins with no `cellComponent`. |

## Marker convention

SpecForm applies anker's §10 rule automatically — one convention per
form, chosen from the schema: when required fields are the strict
majority, optional fields get the muted `optionalMarker` and asterisks
are suppressed; otherwise required fields get the standard `*`. Group
children count toward the majority; section markers don't. Read mode
shows no markers. Standalone `FieldRenderer` (outside SpecForm) falls
back to anker's default (asterisks on required fields).

## Section Partitioning

`partitionSchemaBySections` (pure, shared with the spec editor) splits the
flat `schema` array at each `section` field:

- Fields before the first `section` field form an **implicit first tab**,
  labeled with `labels.defaultTab` (default `"General"`).
- Each `section` field opens a new tab named after the section's `name`.
- A schema with **no** `section` fields is "sectionless" — `SpecForm` skips
  tabs entirely and renders `FieldRenderer` directly against the flat field
  list.
- Tab orientation (`"horizontal" | "vertical"`) is a whole-form setting read
  from the **first** section's `settings.orientation` only; later sections
  cannot override it.

## Card Layout

A `card` field is a layout marker one level below `section`: within a tab,
fields after a `card` marker belong to that card until the next `card` or
`section` marker (`partitionTabByCards`, pure and shared with the spec
editor). Cards are purely visual — fields keep their top-level accessors
and stored values are byte-identical with or without markers.

- **Stacked**: one full-width card per row, in schema order — no
  side-by-side grid, no per-card widths.
- **Title optional**: the marker's `config.name`, rendered as a small
  heading when non-empty; an untitled card is a plain box with no header.
- **All-in-cards per tab**: once a tab contains a card marker, every field
  in that tab should live in a card. `validateSpec` flags violations per
  loose field (`loose_field_in_carded_tab`) — but **rendering never breaks
  on a violation** (normative): leading loose fields render as an implicit
  untitled card.
- Tabs without cards render exactly as before — no wrapper element.
- Read mode renders the same card boxes with description-list rows inside.
- Field search, cross-tab jump, submit-jump-to-first-error, and tab error
  badges are unchanged — they operate on the flat field list and DOM ids;
  card markers are never search results.
- The loading skeleton draws its rows inside card frames when the first
  tab has cards.
- `EditDrawer` inherits cards through `SpecForm`; `SpecDataTable` ignores
  card markers exactly as it ignores sections.

## Mounted-Hidden Panels

All tab panels stay mounted in the DOM at all times (`Tabs.Root` is never
given `lazyMount`/`unmountOnExit`) — only the active panel is visible.
React Hook Form registers every field via `useFormContext`, so unmounting an
inactive tab would unregister its fields and drop their values. This also
means validation, dirty state, and errors are always live for every tab, not
just the one currently in view.

### Your `<form>` must carry `noValidate`

Hidden-but-mounted panels and native browser validation don't mix. Field
components render the native `required` attribute, and a browser refuses to
submit a form holding an invalid control it cannot focus — which is precisely
a required-empty field on an inactive tab. The submit is dropped, React Hook
Form never runs, and Save appears to do nothing at all.

So the consumer's form element needs `noValidate`, and the generated Schema
does the validating:

```tsx
<form noValidate onSubmit={methods.handleSubmit(handleSave)}>
  <SpecForm schema={spec.fields} />
</form>
```

Submit-jump-to-first-error depends on it: the tab can only be switched once
the submit reaches React Hook Form. `EditDrawer` sets it for you.

## Search

A search box (`/` keyboard shortcut, unless focus is already in a text
input/textarea/content-editable element) filters fields by name or accessor
across every tab. The `/` shortcut has full parity between modes: both ask
the shared combobox for it with the same `slashShortcut` prop (rather than
each mode implementing a listener), so it focuses the search box in edit and
read mode alike. If more than one `SpecForm`/search box is mounted at once,
each claimant registers its own listener and the **first-mounted** one wins:
listeners fire in registration order, and the first one to run focuses its
own input synchronously — by the time later listeners run, focus is already
inside a text input, so their own skip-while-typing guard makes them
early-return.

The dropdown itself is `SearchCombobox` (`src/renderer/search-combobox.tsx`),
which is agnostic about what it lists: a caller supplies its own result type,
its own matching, and a `describeResult` saying how one result reads — a
primary label and an optional secondary line, shown trailing the label
(`layout="inline"`, the default) or beneath it (`layout="stacked"`).
`FieldSearch` is the field-shaped caller: it knows an index of fields and
describes each result as a field name plus the tab it sits on. Everything
else — the listbox roles, the active-descendant wiring, the keyboard model
and the Escape containment below — is the combobox's, once, for every caller.

A caller's `search` answers with a `SearchComboboxAnswer<T>`: the `results` to
list and, optionally, a `countLabel` shown above them. Both travel in one
answer so a caller that caps its list cannot compute the list and the sentence
about it from two different questions — that is the Reference Field's Find,
which lists at most twenty matches and says how many it found. `FieldSearch`
passes no `countLabel` and shows no count line: a Spec's fields are a set an
Author already scrolls in full.

Because that race is first-mounted-wins, the claim is **opt-in**: the
combobox registers no document- or window-level key listener unless a caller
asks for the shortcut. `SpecForm`'s field search asks (both modes), and so
does the editor canvas — each owns the screen it sits on. A search nested
inside one of those screens must not ask, since it could only ever lose the
race and would be registering a listener that can never fire.

Use `ArrowUp`/`ArrowDown` to move the highlight, `Enter` to jump to the
highlighted result, `Esc` to clear the query. Jumping switches to the target
tab, then — one frame later, once the panel is visible — focuses the field
(edit mode) or scrolls to and briefly highlights its row (read mode). The
read-mode jump is scoped to this `SpecForm` instance's own root (not
`document`), and the target accessor is passed through `CSS.escape()` before
being used in an attribute selector, so dotted/nested accessors and multiple
mounted instances don't collide. The search box is hidden when the schema
has fewer than one searchable field. Its accessible name is
`labels.searchLabel`.

An empty result set renders `labels.noResults` in a `role="status"` element
outside the listbox — announced to assistive tech — while the (empty)
listbox itself stays mounted so `aria-controls` never points at a removed
node. On anker ≥3.2, jumping to a result (`Enter` or a click) or pressing
`Esc` also clears the input's visible text via `SearchInput`'s imperative
`clear()` (in addition to clearing the internal query state, which alone
already closes the dropdown). On anker 3.1, that imperative clear is
skipped by a type guard (under React 19 the ref points at the raw input
element, which has no `clear()`), so the typed text stays visible after a
jump — behavior matches 0.3.2 there.

### Escape containment inside a host drawer

`Esc` is contained so it never escapes to a dialog/drawer ancestor while the
dropdown is open **and the Escape targets the search UI**. This matters because
Ark/zag's dismissable layer (which powers anker's `DrawerRoot`) listens for
`Escape` on `document` in the **capture** phase — capture runs outermost-first,
so a bubble-phase `stopPropagation()` on the search input would always lose the
race and let the same keypress close the host drawer, discarding in-progress
edits. The combobox instead registers its own `window`-level, capture-phase
`keydown` listener, but **only while its dropdown is open** (mounted/torn
down in a **layout** effect keyed on that open state). A capture listener on
`window` always fires before one on `document` — regardless of registration
order — so it reliably wins.

The effect is a **layout** effect rather than a passive one, and the contract
below depends on that. `open` is derived synchronously from the query, so the
listbox and `open === true` land in one render — but that render is reached
from anker's **debounced** `onSearch`, i.e. from a timer rather than from a
discrete user event, and React defers a timer-lane render's passive effects to
a later task instead of flushing them with the render. A passive listener
therefore attaches after the dropdown is already painted, leaving a window in
which the dropdown is visible and Escape is *not* contained; a press landing
there closes the host drawer, which is what the containment exists to stop. A
layout effect runs before paint, so "visible" and "contained" cannot separate
(#82). The sibling containment in `reference-insert-strip.tsx` is a passive
effect for the reason its own comment gives — its gate is set by a discrete
focus event, whose passive effects React flushes with the render — so the two
differ by gate, not by pattern.

Before calling `stopPropagation()`, it checks
whether the event target is inside this search UI's own container; Escapes
aimed elsewhere (e.g. a keyboard drag in the editor canvas whose cancel
listens on document-bubble) are allowed to propagate untouched.

The contract: **Escape with the dropdown open and targeting the search UI
clears the query and closes only the dropdown — a host drawer never closes
on that keypress.** Escape pressed again with the dropdown already closed is
not intercepted (no listener is mounted), so it propagates normally and closes
the host drawer. Escapes aimed outside the search UI, even while the dropdown
is open, also propagate normally. See the `InDrawerWithSections` story below
and `__tests__/drawer-escape.test.tsx` (mounts a real anker `DrawerRoot`, not
a bare-div stand-in) for the proof.

## Read Mode

`mode="read"` takes a `values` object directly and needs **no**
`FormProvider` in the tree — it never calls `useFormContext`/`useFormState`.
Each field's value is resolved in this order:

1. Empty values (`undefined`, `null`, `""`, or an empty array) render an
   em dash (`—`).
2. Otherwise, the field type's own `readComponent`, when the plugin declares
   one. This is where a type whose reading differs from its table cell says
   so, and read mode names no field type to find it (ADR-0007). It receives
   `field`, `value`, and a `renderChild(field, value)` callback that runs this
   same four-step resolution — so a container renders what it holds without
   read mode knowing what that is. Three built-ins declare one:
   - `group` renders each item as its own indented row of child fields, where
     its cell counts them;
   - `single_reference` resolves the referenced Content's name through the
     reference adapter, falling back to the id;
   - `reference` (and every type minted by `createReferencePlugin`) renders
     the resolved tree — names through the adapter, indented by depth, each
     Reference's Attribute values against it — where its cell counts. Past
     the tree's collapse threshold it opens folded and carries a Find
     control and a Collapse all that returns it to the set it opened in,
     over the same functions the editable tree folds and Reveals with;
     nothing it does writes.

   A cell can do none of this: it has neither adapter access nor async
   (ADR-0008). Read mode sits inside the renderer, so it has both.
3. Otherwise, the field type's registered `cellComponent` (the same one used
   by `SpecDataTable`) renders the value — the ordinary case.
4. If no `cellComponent` is registered for the field type, a type-aware
   fallback formats the value: booleans render as `labels.booleanYes`/
   `labels.booleanNo` (not `String(value)`'s `"true"`/`"false"`), and arrays
   of only strings/numbers/booleans are joined with `", "` (booleans inside
   the array use the same labels). Objects, and arrays containing an object,
   fall back to the em dash — a plugin with non-string values should ship a
   `cellComponent`, or a `readComponent` when reading wants more than a cell
   can give. Anything else (strings, numbers) passes through `String(value)`
   unchanged.

Because read mode has no form state, there are no dirty dots or error
badges on its tabs, and no submit-jump behavior.

## Degrading Orientation

Vertical tabs need a side nav column, which doesn't fit in narrow
containers (drawers, modals). `SpecForm` observes its own container width
via `ResizeObserver` and **auto-degrades a `vertical` orientation to
`horizontal` below ~560px container width** — this applies whether the
narrow container is a drawer, a modal, or just a small browser window.

## Loading

`loading` renders `SpecFormSkeleton` — a placeholder tab strip (shown only
when the schema has sections) plus up to 8 skeleton rows — instead of the
schema. Useful while a spec or its data is still being fetched.

## In a Drawer

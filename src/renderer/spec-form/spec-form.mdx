# SpecForm

Renders a full specification as a form, automatically splitting it into
section tabs when the schema contains `section` fields. Wraps
[FieldRenderer](?path=/story/renderer-fieldrenderer--default) and adds
tabbed navigation, cross-tab field search, per-tab dirty/error indicators,
submit-jump-to-error, a loading skeleton, and a form-free read mode.

## When to Use

`FieldRenderer` stays public for flat embedding (groups use it internally to
render each item's child fields); embed `SpecForm` unless you know why not.
It is the entry point consumers should reach for when rendering a
specification end to end — including specs with no sections at all, where it
behaves identically to `FieldRenderer`.

## Props

| Prop       | Type                       | Default  | Description                                                        |
|------------|----------------------------|----------|---------------------------------------------------------------------|
| `schema`   | `Schema`                   | —        | The field specification to render.                                  |
| `mode`     | `"edit" \| "read"`         | `"edit"` | `"read"` renders values via table cell components instead of inputs. |
| `readOnly` | `boolean`                  | —        | Edit-mode only; disables inputs but keeps the form interactive.      |
| `loading`  | `boolean`                  | —        | Renders `SpecFormSkeleton` instead of the schema.                    |
| `values`   | `Record<string, unknown>`  | `{}`     | Read-mode data source. Ignored in edit mode.                         |
| `labels`   | `SpecFormLabels`           | —        | Overrides for the default-tab name, search placeholder, no-results text, markers, and indicator announcements. |

`SpecFormLabels` fields (`defaultTab`, `searchPlaceholder`, `searchLabel`,
`noResults`, `optionalMarker`, `tabErrors`, `tabErrorsOne`, `unsavedChanges`)
are all optional and merge over `DEFAULT_LABELS`.

| Label | Default | Description |
|-------|---------|--------------|
| `optionalMarker` | `"(optional)"` | §10 marker shown after non-required labels when the form is mostly required. |
| `searchLabel` | `"Find field"` | Accessible name (aria-label) of the field-search input. |
| `tabErrors` | `"{count} invalid fields"` | Accessible name of a tab's error badge; `{count}` is interpolated. |
| `tabErrorsOne` | `"1 invalid field"` | Accessible name of a tab's error badge at count 1 — used instead of `tabErrors` so the badge reads as a grammatical singular. |
| `unsavedChanges` | `"Unsaved changes"` | Accessible name of a tab's dirty dot — and, on anker ≥3.2, of a dirty field's own per-field dot. On anker 3.1 the per-field dot is still labeled, just with anker's hardcoded German default rather than this override, which only takes effect on ≥3.2. |

## Marker convention

SpecForm applies anker's §10 rule automatically — one convention per
form, chosen from the schema: when required fields are the strict
majority, optional fields get the muted `optionalMarker` and asterisks
are suppressed; otherwise required fields get the standard `*`. Group
children count toward the majority; section markers don't. Read mode
shows no markers. Standalone `FieldRenderer` (outside SpecForm) falls
back to anker's default (asterisks on required fields).

## Section Partitioning

`partitionSchemaBySections` (pure, shared with the spec editor) splits the
flat `schema` array at each `section` field:

- Fields before the first `section` field form an **implicit first tab**,
  labeled with `labels.defaultTab` (default `"General"`).
- Each `section` field opens a new tab named after the section's `name`.
- A schema with **no** `section` fields is "sectionless" — `SpecForm` skips
  tabs entirely and renders `FieldRenderer` directly against the flat field
  list.
- Tab orientation (`"horizontal" | "vertical"`) is a whole-form setting read
  from the **first** section's `settings.orientation` only; later sections
  cannot override it.

## Mounted-Hidden Panels

All tab panels stay mounted in the DOM at all times (`Tabs.Root` is never
given `lazyMount`/`unmountOnExit`) — only the active panel is visible.
React Hook Form registers every field via `useFormContext`, so unmounting an
inactive tab would unregister its fields and drop their values. This also
means validation, dirty state, and errors are always live for every tab, not
just the one currently in view.

## Search

A search box (`/` keyboard shortcut, unless focus is already in a text
input/textarea/content-editable element) filters fields by name or accessor
across every tab. Use `ArrowUp`/`ArrowDown` to move the highlight, `Enter` to
jump to the highlighted result, `Esc` to clear the query. Jumping switches to
the target tab, then — one frame later, once the panel is visible — focuses
the field (edit mode) or scrolls to and briefly highlights its row (read
mode). The search box is hidden when the schema has fewer than one
searchable field. Its accessible name is `labels.searchLabel`.

An empty result set renders `labels.noResults` in a `role="status"` element
outside the listbox — announced to assistive tech — while the (empty)
listbox itself stays mounted so `aria-controls` never points at a removed
node. On anker ≥3.2, jumping to a result (`Enter` or a click) or pressing
`Esc` also clears the input's visible text via `SearchInput`'s imperative
`clear()` (in addition to clearing the internal query state, which alone
already closes the dropdown). On anker 3.1, that imperative clear is
skipped by a type guard (under React 19 the ref points at the raw input
element, which has no `clear()`), so the typed text stays visible after a
jump — behavior matches 0.3.2 there.

## Read Mode

`mode="read"` takes a `values` object directly and needs **no**
`FormProvider` in the tree — it never calls `useFormContext`/`useFormState`.
Each field's value is resolved in this order:

1. Empty values (`undefined`, `null`, `""`, or an empty array) render an
   em dash (`—`).
2. Otherwise, the field type's registered `cellComponent` (the same one used
   by `SpecDataTable`) renders the value. `group` fields are the exception:
   they bypass their `cellComponent` entirely and instead render each item
   as its own indented row of child fields.
3. If no `cellComponent` is registered for the field type, the raw value is
   coerced with `String(value)`.

Because read mode has no form state, there are no dirty dots or error
badges on its tabs, and no submit-jump behavior.

## Degrading Orientation

Vertical tabs need a side nav column, which doesn't fit in narrow
containers (drawers, modals). `SpecForm` observes its own container width
via `ResizeObserver` and **auto-degrades a `vertical` orientation to
`horizontal` below ~560px container width** — this applies whether the
narrow container is a drawer, a modal, or just a small browser window.

## Loading

`loading` renders `SpecFormSkeleton` — a placeholder tab strip (shown only
when the schema has sections) plus up to 8 skeleton rows — instead of the
schema. Useful while a spec or its data is still being fetched.

## In a Drawer

`SpecDataTable`'s `EditDrawer` renders row edits through `SpecForm`. See the
[SpecDataTable "Editable" story](?path=/story/table-specdatatable--editable)
for that flow rather than duplicating it here.

# Rich Text

A rich-text document, written in knkeditor under the Text Type the Field pins.

**Editing needs `@knkcs/fieldkit/rich-text`** (ADR-0026). The core renderer shows a `rich_text` Field **read-only**: the document's text, and a line saying it can't be edited here. A Consumer opts into the knkeditor-backed field by passing `knkRichTextPlugin` from that subpath in place of the built-in plugin (`{ ...richTextPlugin, fieldComponent: KnkRichTextField, readComponent: KnkRichTextRead }`), so only Consumers who import it pay for knkeditor's peers. See [Knk Rich Text Field](?path=/docs/rich-text-knk-rich-text-field--docs) and `docs/knkeditor-reference.md`.

## When to Use

Use **Rich Text** for structured, formatted content whose vocabulary a Text Type governs. For lightweight formatting, use [Markdown](?path=/docs/fields-markdown--docs). For plain text, use [Textarea](?path=/docs/fields-textarea--docs).

## Settings

| Setting       | Type                   | Default  | Description                                    |
|---------------|------------------------|----------|------------------------------------------------|
| `text_type`   | `string`               | —        | The Text Type Release the rich text is written in: a Pin (ADR-0020), resolved into the Resolved Spec's `parts.text_type`. The config panel lists them from `adapters.textType.list()` |
| `view_mode`   | `"full" \| "compact"`  | `"full"` | The knkeditor-backed field's editor: `full` is knkeditor's default view, `compact` its minimal one |

The settings are strict: the legacy `editor_spec` is an `unknown_setting` since 0.18.0 (#216). Migrate a Spec holding it by renaming the key to `text_type` and pointing it at a Text Type Release.

## Validation

The Zod schema accepts any object (a ProseMirror document); anything else is refused. What the document may hold is knkeditor's to say under the Field's Text Type, which fieldkit's Go module checks (`invalid_rich_text`); TS has no knkeditor validator.

## Zod Output

```ts
// Always
z.record(z.unknown())
```

## Table Cell

Renders a plain-text extraction via `RichTextCell`, walking the document's `content` tree for its text nodes. Falls back to `"[Rich text content]"` for unrecognized structures. Truncated at 100 characters.

## Known Limitations

- The core renderer's field is read-only: it never writes the value, so the form keeps the document as it came. A JSON textarea used to stand here, and let anyone write documents knkeditor refuses.
- TS validates only that the value is an object; knkeditor's validation, edges, text, Compare and Merge run in fieldkit's Go module (`docs/knkeditor-reference.md`)

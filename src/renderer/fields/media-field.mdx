# Media

Upload a new file or pick an existing one. Stored files are listed by name, type and size. Requires a `media` adapter to be configured via `FieldKitProvider` (ADR-0029).

## When to Use

Use **Media** for file uploads such as images, documents, or other attachments. The field stores an array of asset ids; the adapter names them.

## Settings

| Setting     | Type       | Default     | Description                                    |
|-------------|------------|-------------|------------------------------------------------|
| `accept`    | `string[]` | `undefined` | Allowed MIME types (e.g. `["image/jpeg", "image/png"]`). Filters the upload dialog and is passed to `browse` as `mime_types`. |
| `max_items` | `number`   | `undefined` | Maximum number of files allowed. When the limit is reached, upload and the picker are hidden. |

## Adapter Interface

The media field requires a `media` adapter injected via `FieldKitProvider`:

```ts
media: {
  upload: (file: File, context: MediaUploadContext) => Promise<MediaItem>;
  browse?: (filter: MediaFilter) => Promise<MediaItem[]>;
  resolve?: (ids: string[]) => Promise<ResolvedMediaItem[]>;
}
```

- **`upload`** receives the Field as `context.field`, so the Consumer — not the Spec — decides where a file is stored.
- **`browse`** is the picker's source. It is asked only once somebody opens the picker, with what they typed and the Field's `accept`: `{ query, mime_types }`. Assets the Field already holds are dropped from the answer. **Without `browse` the field offers upload only** (ADR-0027).
- **`resolve`** names stored ids, deleted assets included (`deleted: true`, shown marked and still removable). An id it leaves out — or every id, without `resolve` — shows as itself.

Where `MediaItem`, `ResolvedMediaItem`, `MediaFilter` and `MediaUploadContext` are:
```ts
interface MediaItem {
  id: string;
  filename: string;
  url: string;
  mime_type: string;
  size: number;
  [key: string]: unknown;
}

type ResolvedMediaItem = MediaItem & { deleted?: boolean };

interface MediaFilter {
  mime_types?: string[];
  query?: string;
}

interface MediaUploadContext {
  field: Field;
}
```

A rejected `upload` or `resolve` is reported through `FieldKitProvider`'s `onError`; a failed upload also says "Upload failed" under the field.

## Validation

| Rule       | Type     | Description                                     |
|------------|----------|-------------------------------------------------|
| `required` | `boolean`| When true, at least one file must be uploaded    |

## Zod Output


## Table Cell

With the adapter's `resolve`, `MediaCell` names its files ("a.pdf, b.pdf (deleted)"), counting them while the names are on their way. Without it, it renders a file count (e.g. "3 files", "1 file"). Shows an em-dash for null/empty values.

## Known Limitations

- No image preview (`MediaItem.url` is unused)
- No drag-and-drop upload
- `max_items` is not reflected in the Zod schema
- No file size limit setting
- No single-item mode (always stores an array)
- `browse` answers one list — the picker does not page

# Group

A repeating group of child fields. Each item in the group contains the same set of fields. Uses React Hook Form's `useFieldArray` for dynamic add/remove.

## When to Use

Use **Group** when you need a repeating set of structured fields (e.g., links with label+URL, team members with name+email+role). For unstructured key-value pairs, use [Array](?path=/docs/fields-array--docs). For heterogeneous content, use [Blocks](?path=/docs/fields-blocks--docs).

## Settings

| Setting     | Type     | Default | Description                                    |
|-------------|----------|---------|------------------------------------------------|
| `min_items` | `number` | —       | Minimum number of items (enforced in Zod and UI) |
| `max_items` | `number` | —       | Maximum number of items (enforced in Zod and UI) |

## Children

The `children: Field[]` property on the field definition defines the child fields rendered within each group item. Each child field uses the standard `Field` interface.

## Validation

The Zod schema validates the array length via `min_items`/`max_items`, and each
row against the child fields it holds: a required field left empty in row 2
blocks submit and reports at `authors.1.name` — the path the renderer registers
it under, so React Hook Form puts the message on that row's field rather than on
the Group (ADR-0007). Children obey the same rules their top-level siblings do:
markers and hidden fields are skipped, optional children accept the empty string.

Rows are `passthrough`: a stored row carries more than the spec edits — a
backend id, most obviously — and validating rows doesn't prune the rest on
submit. A Group with no children keeps the opaque row it always had.

## Zod Output

```ts
// No children
z.array(z.record(z.unknown()))

// Children `name` (required) and `role` (optional)
z.array(z.object({ name: z.string().min(1), role: z.string().optional() }).passthrough())

// With min/max
z.array(row).min(1).max(5)
```

## Table Cell

Renders the item count via `GroupCell`.

## Known Limitations

- No drag-to-reorder (the plan specified dnd-kit integration)
- `append({})` ignores child field defaults — new items start with empty objects. Now that rows validate, an added row is invalid until its required fields are filled, which is the intent; but a child with a plugin default (a boolean's `false`) starts undefined rather than seeded.
- No collapse/expand per item
- "Add item" button is above the list instead of below
